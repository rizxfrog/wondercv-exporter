# WonderCV 简历导出脚本 —— 逆向分析与实现总结

> 目标：在超级简历（WonderCV）编辑器页，绕过预览水印、不碰服务端付费导出接口，用官方自己的渲染结果本地导出可携带 PDF。
> 环境：`https://www.wondercv.com/cvs/{token}/editor`，已登录态，Chrome + js-reverse MCP。

---

## 一、整体思路演进

| 版本 | 思路 | 结果 |
|---|---|---|
| v1–v2 | `fetch` 官方 `online_cv_format` JSON → 自己写 HTML/CSS 复刻模板 | 可用但样式简陋，距官方预览差距大 |
| v3 | 接住 `format_info` 排版参数，多模板引擎（tag/strip/default 标题 + block 默认头部） | 彩带削顶、照片掉落——自己写 CSS 还原度永远有差 |
| **v4** | **不解析**：克隆官方预览 DOM + 内联官方样式表 + 去水印 | 100% 一致，验证通过 |

核心结论：**与其逆向"样式解析逻辑"，不如直接搬运官方渲染结果**。预览窗格 `.resume-main` 就是官方渲染产物，连同它的 CSS 一起搬走，任何模板自动一致。

## 二、关键发现（事实清单）

1. **技术栈**：Vue 3 SPA，Vite 构建（`cv_pc_vue`），产物含 `chunk-vuex / chunk-axios / chunk-js-cookie / chunk-dayjs` 等 hash 化 chunk。
2. **预览容器**：`.resume-main.resume-component-class-name-512688`（类名带随机后缀），真实内容宽度 **708px**（= A4 内容宽）；无 iframe，在主文档里。
3. **内容异步挂载**：简历正文在 `#cv-container`（类 `is-page-margin`，外层 `.scale` 带 `transform: scale(0.89)`）内，**Vue 异步填充**，空挂载态下 `#cv-container.children=0`。
4. **水印位置**：背景图 `https://files.wondercv.com/pc-vue/editor/editer-preview-watermark.png`，挂在每页纸张容器 `.one-page-container` 上；
   - `background-repeat: no-repeat`
   - `background-position: 50% 50%`（页面正中）
   - `background-size: 70%`（占页面宽 70% 的居中大图）
   - 非 DOM 文本节点、非伪元素（`::before/::after` 的 `content` 均为 `none`）。
5. **反调试陷阱**：站点含 `startMonitorConsoleOpen` 函数，体内有 `debugger;` 语句，打开 DevTools/断点时触发，会暂停脚本执行。
6. **第三方脚本/埋点**：Microsoft Clarity、GrowingIO、百度统计、360（`jspassport.qhimg.com`）、Geetest 验证码——纯观测，与导出无关。
7. **API 基址**：`https://api.wondercv.com/cv`，版本化路径 `/cv/v1|v3|v4`，简历接口 `GET /cv/v3/cvs/{token}/online_cv_format`，鉴权 `Authorization: {_t cookie}`。

## 三、踩坑记录（按时间线）

### 坑 1：自己写 CSS 复刻，样式永远对不齐
- **现象**：v3 彩带标题文字被削顶、照片掉到头部下方。
- **根因**：把彩带高度做在 `border-bottom` 上（`height:0` 容器），文字没有流内空间；default 头部没做 flex，头像块级换行。本质是"猜官方 CSS 规则"。
- **解法**：放弃手写复刻，改 v4 直接克隆官方 DOM。

### 坑 2：`.resume-main` 取出来是空壳（outerHTML 只有 `<div class="scale">`）
- **现象**：`document.querySelector('.resume-main').outerHTML` 只有占位节点，内容在 `#cv-container` 但 `children=0`。
- **根因**：探测时刻 Vue 未挂载内容（后台标签页被卸载 / 重渲染竞态）。
- **解法**：`waitForContent()` 轮询 `#cv-container.children.length > 0`（最多 8s）后再克隆。

### 坑 3：克隆后模板样式全部失效（整页无版式）
- **现象**：内联了 1.4MB CSS，但蓝色色块头部、彩带标题、两栏布局全不生效。
- **根因**：官方 CSS 是 Vue scoped 样式，选择器形如 `.foo[data-v-e0332d32]`；克隆 DOM 节点上的 `data-v-*` 哈希与当下加载的 CSS 版本哈希**不一致**，规则匹配失败。
- **解法**：序列化 CSS 后统一 `replace(/\[data-v-[a-f0-9]+\]/g, '')`，退化为类选择器全局命中（导出页只有简历 DOM，无副作用）。

### 坑 4：CSS 太大被限量跳过，导致姓名不显示
- **现象**：去掉 scoped 后姓名「超级简历」仍不显示。
- **根因**：`index-CUa4__ic.css` 有 **5MB**（含巨量模板/字体规则），首版组装时加了 `t.length>2000000 continue` 上限把它丢掉了，`.user-name` 等核心规则就来自这里。
- **解法**：去掉大小上限，整表全量序列化（浏览器扛得住，本机也只在页面上下文读）。

### 坑 5：本机代理把 CDN 响应体空化，验证出现假阴性
- **现象**：headless Chrome 渲染导出页"看不到水印"，以为清干净了；用户浏览器里水印还在。
- **根因**：本机 `https_proxy=127.0.0.1:7897` 对 `static.wondercv.com` / `files.wondercv.com` 返回 HTTP 200 但 **body 为空**（TLS 握手成功、响应体被代理吞掉）。`curl`/`fetch` 拿到的 CSS 与 PNG 都是 0 字节。
- **解法**：**不依赖本机下载**。CSS 直接从页面 `document.styleSheets[i].cssRules` 在页面上下文序列化（同源读取不受代理影响）；**验证必须走真实浏览器页面**（它的会话能正常拉图），而非本机 headless。

### 坑 6：水印覆盖选择器写错，水印清除失效
- **现象**：用户反馈导出仍有水印。
- **根因**：覆盖规则写成了 `.main-one-page-container`（把 probe 输出的 `main main- one-page-container` 几个类名错误拼成了一个），**匹配不到任何节点**，外部 CSS 的水印背景原样生效。
- **解法**：双保险——
  - (A) 克隆时在原树用 `getComputedStyle` 找 `backgroundImage` 含 `watermark` 的节点，在克隆树对应节点精确内联 `background-image: none !important`；
  - (B) CSS 兜底改对：`[class*=one-page-container], [class*=watermark] { background-image: none !important }`（子串匹配防类名版本漂移）。

### 坑 7：编辑筛选误删内容
- **现象**：早期宽松匹配 `[class*=edit]` 在个别模板上误删正文节点。
- **解法**：保留 `[class*=edit]` 等，但**删错的内容在预览里一眼可见**，且导出页只用于打印，可接受小范围删改；真正危险的是把"内容"当"控件"删——用 `button, [class*=picture-delete]` 等更具体选择器兜底。

### 坑 8：按钮"点了没反应"
- **现象**：用户点导出按钮无任何反馈。
- **根因**：上一轮改水印覆盖时误删了 `const css = serializeCss() +` 这一行，导致 `exportPreview` 中 `const html = ... "<style>" + css + ...` 引用的 `css` 从未声明；严格模式抛 `ReferenceError: css is not defined` → 被 `catch` 捕获 → `alert()` 在内容脚本里被静默拦截 → 表现为"没反应"。
- **解法**：补回 `const css = serializeCss() +`，语法校验 + 引用一致性确认。

### 坑 9：`debugger` 反调试陷阱中断导航/取值
- **现象**：`navigate_page` / `evaluate_script` 常报告"paused at breakpoint"。
- **根因**：站点 `startMonitorConsoleOpen` 内置 `debugger;`。
- **解法**：捕获到 `get_paused_info` 显示 `reason: other` + `debugger` 时，直接 `pause_or_resume(action:"resume")` 放行。

## 四、最终方案（v4 管线）

```
点击按钮
  └─ waitForContent()          轮询 #cv-container 有内容（最多 8s）
  └─ clone = cleanClone(root)
        ├─ cloneNode(true) 复制 .resume-main 子树
        ├─ 遍历原树：computed backgroundImage 含 watermark → 克隆树对应节点内联 background:none!important
        └─ 删 button / [class*=edit|delete|handle|toolbar|add-module|operate|picture-delete]
  └─ css = serializeCss()      遍历 document.styleSheets：同源 wondercv/alicdn 表读 cssRules
        ├─ 剥离 [data-v-*]
        └─ 追加兜底：[class*=one-page-container],[class*=watermark]{background-image:none!important} + @page A4 + print-color-adjust
  └─ 新窗口写入 <style>css</style> + clone.outerHTML
  └─ 1.5s 后 window.print()
```

## 五、验证方法（关键纪律）

- **绝不信任本机 headless 验证**：代理吞图，会假阴性。
- **用真实浏览器页面验证**：把导出 HTML 用本地 HTTP 服务（`python3 -m http.server`）供页面加载，在能正常拉取 wondercv 资源的会话里打开、截图确认无水印 + 样式一致。
- **节点级证据优先**：用 `getComputedStyle(node).backgroundImage` 直接读数确认水印载体与清除效果，而非肉眼猜。
