# 超级简历（WonderCV）编辑器 —— 逆向分析报告

**分析对象**：`https://www.wondercv.com/cvs/{token}/editor`（简历在线编辑器 / 预览页）
**分析手段**：js-reverse MCP（Chrome DevTools 协议），已登录态
**分析目标**：理清前端技术栈、渲染管线、水印机制与接口鉴权，评估"本地无水印导出"的可行路径

---

## 1. 前端技术栈

| 维度 | 发现 |
|---|---|
| 框架 | Vue 3（SPA），`window.__vue_app__` 可访问；模板用 `data-v-*` scoped 属性 |
| 构建 | Vite，`cv_pc_vue` 产物，文件名 hash 化（`index-DEZX7raY.js`、`resume-mQyjJfQn.css`）|
| 状态/请求 | vuex + axios（`chunk-vuex / chunk-axios / chunk-js-cookie / chunk-dayjs`）|
| 富文本 | wangeditor + quill + tinymce（多套编辑器 chunk 并存）|
| 预览渲染 | 客户端纯 DOM+CSS 渲染（无 canvas/服务端截图），水印是 CSS 背景图 |

**证据**：`list_scripts` 返回 79 个脚本，`static.wondercv.com/cv_pc_vue/static/{js,css}` 下 hash 化 chunk；`document.styleSheets` 含 `resume-mQyjJfQn.css`（201KB，模板样式核心）、`index-CVg-dbP9.css`（512KB）、`index-CUa4__ic.css`（5MB，全模板/字体规则）。

## 2. 渲染管线

```
GET /cvs/{token}/editor
  └─ Vue 挂载编辑器布局（左：表单编辑区  右：预览窗格）
预览窗格结构：
  .resume-main.resume-component-class-name-512688.cn.a4   （@page A4 尺寸，708px 宽）
    └─ .scale  （transform: scale(0.89) 适配预览缩放）
        └─ #cv-container.is-page-margin
            └─ .main.one-page-container.page-index-N   （每页纸张；水印背景在此）
                └─ .content.main-page-N  →  各 section（标题/头部/正文）
```

- **内容来源**：编辑器表单改动 → Vuex 更新 → `#cv-container` 内组件异步重渲染。导出时**克隆已挂载的 DOM 即可获得完整渲染结果**，无需重放接口。
- **关键事实**：`#cv-container` 在后台标签 / 重渲染态下可能为空（`children=0`），必须等其挂载。

## 3. 水印机制（重点）

| 项 | 值 |
|---|---|
| 载体 | `.main.one-page-container.page-index-N`（每页纸张容器，多页则多个）|
| 属性 | `background-image` |
| 资源 | `https://files.wondercv.com/pc-vue/editor/editer-preview-watermark.png` |
| `background-repeat` | `no-repeat` |
| `background-position` | `50% 50%` |
| `background-size` | `70%` |
| 触发 | 仅页面预览/编辑态；服务端付费导出 PDF 不含此图 |

**逆向结论**：
- 水印**不是** DOM 文本节点（页面内无含「超级简历」的旋转文本）。
- 水印**不是**伪元素（`.resume-main` 及其祖先 `::before/::after` 的 `content` 均为 `none`）。
- 水印**是**纯 CSS 背景图，挂在预览纸张容器上。
- 因此清除路径明确：压制该容器的 `background-image` 即可，**不进入简历数据、不影响正文**。

## 4. 接口与鉴权

| 接口 | 方法 | 用途 |
|---|---|---|
| `/cv/v3/cvs/{token}/online_cv_format` | GET | 拉取简历完整 JSON（含 `basic_info/submodule_info/format_info`）|
| `/cv/v3/cvs/{token}` | PUT | 自动保存（autosave）|
| `/cv/v4/banners` | GET | 下载引导 banner |
| `/cv/v3/cvs/{token}/cv_cross_page_config` | POST | 跨页配置 |

- **鉴权**：`_t` cookie（登录态），请求头 `Authorization: {_t}`；`credentials: include`。
- **逆向意义**：客户端可凭本人登录态直接读取自己的简历 JSON，数据归属用户本人。本报告**不调用任何服务端导出/付费接口**，不做会员状态伪造——仅在浏览器本地用官方已渲染 DOM 生成 PDF。

- 站点含 `startMonitorConsoleOpen()`，体内 `debugger;`：检测到 DevTools 打开时持续中断。（不影响正常使用，仅干扰人工调试；自动化执行时 `resume` 即可放行。）
- 第三方脚本埋点：Microsoft Clarity、GrowingIO、百度统计、360  passport（`jspassport.qhimg.com`）、Geetest 验证码——均为观测/风控，与导出无关。
- 无接口层强校验、无水印服务端耦合，本地导出技术可行。

## 6. 可行性评估与最终方案

**结论：可行，且最优解是"DOM 克隆"而非"CSS 解析复刻"。**

| 方案 | 评估 |
|---|---|
| 解析 `format_info` 自写 CSS | 还原度受限（彩带/双栏/装饰花纹需逐个逆向 CSS，成本高、易错）|
| 调用服务端付费导出 | 需伪造/购买会员，违反"不碰付费接口"前提 |
| **克隆官方预览 DOM + 内联官方样式表 + 去水印** | ✅ 渲染 100% 一致，任何模板通用，仅去预览水印 |

**最终导出管线**：
1. 等待 `#cv-container` 内容挂载（轮询 ≤8s）；
2. `cloneNode(true)` 复制 `.resume-main`；
3. 在原树上用 `getComputedStyle` 定位水印背景节点 → 克隆树对应节点内联 `background-image:none!important`；并追加 CSS 兜底 `[class*=one-page-container],[class*=watermark]{background-image:none!important}`；
4. 删除编辑态控件（`button`/`[class*=edit|delete|handle|operate|picture-delete]` 等）；
5. 序列化 `document.styleSheets` 中同源样式表，**剥离 `[data-v-*]` scoped 选择器**，追加 `@page A4` 与 `print-color-adjust:exact`；
6. 新窗口写入 + `window.print()`。

**验证约束**：本机出口代理会空化 `files.wondercv.com` 响应体，故**验证必须在能正常拉取资源的真实浏览器会话中进行**，不可信赖本机 headless 截图（会假阴性）。

## 7. 风险与边界

- **scoped 类名随机后缀**：`.resume-component-class-name-512688`、`.one-page-container` 等带版本后缀，故选择器一律用**子串/属性匹配**而非全名。
- **CSS 体积**：全量序列化约 5.9MB，导出页在浏览器中渲染与打印正常，但**不适合做"另存为小文件"**。
- **编辑控件清理误伤**：极个别模板下宽松类名可能误删非关键节点，打印预览一眼可见，可接受。
- **多页水印**：每页容器独立挂水印，已按节点遍历清除（实测两页场景）。
- **合规边界**：仅用本人登录态、仅去除预览态水印、不触碰服务端导出/付费逻辑——属"对自己数据的本地可携带化"，非对平台付费机制的破解。
